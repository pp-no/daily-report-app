# Issue Solver スキル（3エージェント方式）

GitHub Issue を Planner → Generator → Evaluator の3段階で対応する。

## 全体の流れ

```
Planner（調査・計画）
    ↓ 実装計画書
Generator（実装）
    ↓ 変更済みコード
Evaluator（レビュー）
    ↓ 評価レポート
完了（コミット・Issue クローズ）
```

---

## Step 1: Planner エージェント

**役割**: Issue の内容を理解し、実装計画を立てる。コードは書かない。

**実行内容**:
1. GitHub MCP で Issue の詳細を取得する（タイトル・本文・ラベル）
2. Explore エージェントでコードベースを調査する
   - 影響を受けるファイルを特定する
   - 既存の実装パターン（命名規則・DTO設計・API設計）を把握する
   - 関連するテスト・設定ファイルを確認する
3. 以下の実装計画書を出力する：

```
## 実装計画

### 変更ファイル一覧
- backend/src/.../XxxController.java（新規 or 変更）
- backend/src/.../XxxService.java（変更）
- frontend/src/pages/XxxPage.tsx（変更）
...

### 実装方針
- エンドポイント: METHOD /api/xxx
- バリデーション: ...
- エラーケース: ...
- フロントの変更箇所: ...

### 注意点・制約
- ...
```

---

## Step 2: Generator エージェント

**役割**: Planner の計画書に従いコードを実装する。

**実行内容**:
1. 計画書の「変更ファイル一覧」に従い、各ファイルを Read してから編集する
2. 既存のコードスタイル・命名規則に揃える
3. バックエンドは Gradle でコンパイルチェックする
   ```bash
   cd backend && ./gradlew compileJava
   ```
4. フロントエンドは TypeScript の型チェックをする
   ```bash
   cd frontend && npx tsc --noEmit
   ```
5. エラーがあれば修正してから次のステップへ進む

---

## Step 3: Evaluator エージェント

**役割**: Generator の実装を独立した視点でレビューする。

**実行内容**:
1. 変更されたファイルを Read して実装内容を確認する
2. 以下の観点でチェックする：

| 観点 | チェック内容 |
|---|---|
| 機能 | Issue の要件をすべて満たしているか |
| セキュリティ | 認証・認可の抜け、入力値検証の漏れがないか |
| エラーハンドリング | 異常系（存在しない・権限なし等）を適切に処理しているか |
| 既存機能への影響 | 既存のエンドポイント・コンポーネントへの影響がないか |
| コードスタイル | 既存の命名規則・設計パターンに揃っているか |

3. 以下の評価レポートを出力する：

```
## 評価レポート

### 合格項目
- ...

### 要修正項目（あれば）
- ファイル名:行番号 - 問題の説明・修正案

### 総合判定: ✅ 承認 / ⚠️ 要修正
```

4. 要修正がある場合は Generator に差し戻して修正させる

---

## 完了処理

Evaluator が「✅ 承認」を出したら：
1. `git-commit` スキルでコミットする
2. GitHub MCP で Issue をクローズし、実装内容をコメントする

---

## 注意事項

- Planner はコードを書かない（計画のみ）
- Generator は計画書の範囲外の変更をしない
- Evaluator は Generator とは独立した視点でレビューする（同じ思い込みを持ち込まない）
- 各エージェントは前のエージェントの出力を必ず引き継ぐ
