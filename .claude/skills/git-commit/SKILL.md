# Git Commit スキル

変更内容を確認し、日本語のコミットメッセージを作成してコミットする。

## 手順

1. `git status` で変更ファイルを確認する
2. `git diff` でステージ済み・未ステージの差分を確認する
3. `git log --oneline -5` で過去のコミットメッセージのスタイルを確認する
4. 差分の内容からコミットメッセージを日本語で作成する
5. 関連ファイルをステージングして `git commit` を実行する

## コミットメッセージのルール

- プレフィックスは英語（`feat:` `fix:` `refactor:` `ui:` `chore:` `docs:`）
- 説明は日本語で簡潔に
- Co-Authored-By を必ず末尾に付ける

```
feat: 機能の説明

詳細が必要な場合はここに記述

Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
```

## コミットの取り消し・削除

「コミットを取り消して」「直前のコミットを削除して」などと言われた場合、状況に応じて以下を使い分ける。

### まず状況を確認する
```bash
git log --oneline -5
git status
```

### ケース別の対応

| 状況 | コマンド | 説明 |
|---|---|---|
| 直前のコミットを取り消す（変更は残す） | `git reset --soft HEAD~1` | ステージング状態に戻る |
| 直前のコミットと変更を両方消す | `git reset --hard HEAD~1` | 変更が消えるため要確認 |
| 特定のコミットを打ち消す新コミットを作る | `git revert <hash>` | プッシュ済みの場合に安全 |
| 複数コミットを取り消す（変更は残す） | `git reset --soft HEAD~N` | N に件数を指定 |

### 重要な判断基準

- **プッシュ前** → `git reset` で安全に取り消せる
- **プッシュ済み** → `git reset --hard` + `git push --force` は危険。`git revert` を使う
- `--hard` は変更が消えるため、実行前に必ずユーザーに確認を取る

## 注意事項

- `application.properties` など機密情報を含むファイルはステージしない
- ユーザーから明示的に指示がない限りプッシュはしない
- `.gitignore` に含まれるファイルに注意する
