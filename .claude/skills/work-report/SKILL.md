# 作業報告書生成 Skill

このSkillは、プロジェクトの作業セッション後に構造化された作業報告書をMarkdownで生成する。

## Skillの使い方

### Step 1: コンテキストの収集

**会話履歴から先に情報を抽出する。** 今の会話に作業内容が含まれていれば、わざわざ確認しない。以下の情報を集める：

- **日付**: 今日の日付（システム日付を使用）
- **プロジェクト名**: 作業ディレクトリ名またはCURRICULUM.mdのタイトルから
- **担当者**: git configのuser.nameから取得（`git config user.name`）
- **フェーズ**: CURRICULUM.mdが存在すればそこから読み取る
- **作業内容**: 何をやったか（目的・実施内容・成果物）
- **確認事項・懸念点**: 問題点・制約・注意点
- **次回作業予定**: 次にやること
- **所要時間**: 各作業にかかった時間

### Step 2: 不足情報の確認

会話から得られなかった情報のみ、ユーザーに**まとめて一度だけ**確認する。例：

> 以下の情報を教えてください：
> - 今日の作業内容の概要（1〜2行）
> - 所要時間の内訳
> - 次回の作業予定

情報がすでに揃っている場合はこのステップを飛ばしてよい。

### Step 3: ディレクトリ確認・作成

```bash
mkdir -p docs/reports
```

### Step 4: 報告書を生成する

以下のテンプレートを使って `docs/reports/YYYY-MM-DD_作業報告書.md` を作成する。

---

## 報告書テンプレート

```markdown
# 作業報告書

| 項目 | 内容 |
|---|---|
| 日付 | YYYY年M月D日（曜日） |
| プロジェクト | プロジェクト名 |
| 担当者 | 担当者名 |
| フェーズ | Phase X：フェーズ名 |

---

## 作業概要

（1〜2行のサマリー。何をやって何を達成したか）

---

## 作業内容

### 1. 作業タイトル

**目的：** なぜこの作業をやったか

**実施内容：**
- 箇条書きで具体的な作業内容

**成果物：**
- 作成・変更したファイルやドキュメント

---

### 2. （作業が複数ある場合は繰り返す）

---

## 確認事項・懸念点

| 項目 | 内容 |
|---|---|
| 課題や制約があれば記載 | 詳細 |

（なければ「特になし」）

---

## 次回作業予定

- 次にやること（具体的に）

---

## 所要時間

| 作業 | 時間 |
|---|---|
| 作業1 | 約XX分 |
| **合計** | **約XX分** |
```

---

## 注意点

- ファイル名の曜日は日本語（月・火・水・木・金・土・日）
- 確認事項・懸念点がなければ「特になし」と書く
- 作業内容が会話履歴から明確に取れる場合は、できるだけ詳細に記述する（ファイルパス、コマンド、設定値なども含める）
- 報告書を生成したら、ファイルパスをユーザーに伝える
