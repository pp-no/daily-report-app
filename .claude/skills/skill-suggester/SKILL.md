# Skill Suggester スキル

会話の流れを振り返り、繰り返し登場するパターンをスキルとして提案する。

## 手順

### 1. 既存スキルを確認する

```bash
ls .claude/skills/
```

各スキルの `SKILL.md` を読み、すでにカバーされている操作を把握する。重複提案を避けるため。

### 2. パターンを収集する

以下のソースからパターンを探す：

**会話コンテキスト（最優先）**
- 今回のセッションでユーザーが繰り返した指示・質問
- 毎回ほぼ同じ手順で対応した作業
- 「またこれか」と感じた操作

**git log から推測する**
```bash
git log --oneline -20
```
コミットメッセージのプレフィックスが偏っている作業はスキル候補になりやすい。

### 3. スキル化の判断基準

以下の条件を**複数満たす**ものをスキル候補とする：

| 条件 | 説明 |
|---|---|
| 繰り返し頻度 | 同じセッション内で2回以上、または毎回のセッションで登場する |
| 手順の複雑さ | 3ステップ以上あり、毎回考える必要がある |
| 汎用性 | このプロジェクト固有ではなく、他の作業にも転用できる |
| スキル未カバー | 既存スキルで対応できていない |

**スキル化しない方がよいもの**（提案しない）:
- 1回しか登場していない操作
- コード1行の変更など単純すぎるもの
- 既存スキルで十分カバーできているもの

### 4. 提案レポートを出力する

以下のフォーマットで出力する：

```
## スキル化候補

### 候補1: [スキル名（英語）]
**トリガー例**: 「〇〇して」「△△を実行して」
**繰り返し回数**: 約N回
**概要**: このスキルが自動化する作業の説明（1〜2文）
**スキル化の理由**: なぜスキルにする価値があるか

---

### 候補2: ...

## 今回スキル化不要と判断したもの
- 〇〇: 理由
```

### 5. ユーザーに確認する

提案を出した後、「作成しますか？」と確認する。
承認された候補は `issue-solver` スキルと同じ構造で `.claude/skills/<name>/SKILL.md` を作成する。

## スキルファイルの作成テンプレート

```markdown
---
name: スキル名
description: 1行の説明。トリガーとなる言葉を含める。
---

# スキル名 スキル

## 手順
1. ...
2. ...

## 注意事項
- ...
```

## 注意事項

- 提案は多くても3件まで。絞り込むほど価値が高い
- 「便利そう」より「毎回やっている」を優先する
- スキル名は既存スキルと被らない英単語にする
